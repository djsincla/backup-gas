BackupGAS

A Chrome extension that gets Apps Script code out of the editor and into Drive or a folder on your machine, including the container bound scripts Google gives you no way to download.

Download it Source on GitHub

one / why this exists

Getting a bound script out of Apps Script

I went looking for a way to back up a CRM I had built inside a Google Sheet, and found that Google does not provide one. A script attached to a Sheet is not a Drive file, so Drive has nothing to export, and the editor has no download option. The documented answer is the Apps Script API, which needs a Google Cloud project behind it. On a managed corporate account that is where it stops. I could not create a project, and I could not enable the API in the hidden one Google had already created for me.

  • no:Drive export. A bound script is not a Drive file, so there is nothing there to export.
  • yes:The Apps Script API, or clasp sitting on top of it, right up until your account cannot enable it.
  • always:BackupGAS, which reads the editor page you already have open.

If you have run into Apps Script API has not been used in project NNNN before or it is disabled with no way to fix it, that is the dead end this works around. And if the only copy of your code is sitting in the editor when somebody deletes the Sheet, you are going to have a really bad day.

three / installing it

Installing it

It is not on the Chrome Web Store yet, so it loads unpacked.

  1. Download the zip and unzip it.
  2. Open chrome://extensions.
  3. Turn on Developer mode, top right.
  4. Click Load unpacked and pick the folder.
  5. Pin it from the puzzle-piece menu.

Running a backup

Open the project in the editor, from a Sheet that is Extensions, Apps Script, and let the page finish loading before you click the icon. Files land in Downloads/Apps Script Backups under the project name and a timestamp, one file per script file, with the real names kept.

four / saving to drive

Saving straight to Drive

An extension cannot write to Drive without a Cloud OAuth client, which is the same wall as before, so the files go to a small Apps Script web app that you deploy yourself and that writes them into your own Drive. It is a one time setup and it is the version I actually use.

  1. Open script.new, paste in receiver/Code.gs and save.
  2. Deploy, New deployment, Web app. Access set to Anyone, or to your own organisation if that is all your admin allows.
  3. Open the /exec address it gives you and copy the setup line on that page.
  4. Paste the line into the extension's Settings.

Backups then land in My Drive/Apps Script Backups, under the project name and a timestamp.

The receiver generates its own password and shows it once, on the first visit to that address. It turns away any request without it, only ever creates files, and only writes inside its own backup folder. Worth keeping the setup line to yourself.

five / how it works

How it works

The Apps Script editor is Monaco, and by the time you are looking at a project it already holds every file in memory. Each entry in the file list carries a data-res-id attribute matching the Monaco model that holds that file, so the extension pairs the two up and reads the text straight out of the page. Files you have not opened yet have no model behind them, so it clicks them and waits for the editor to load them before reading.

No API, no Cloud project and no admin involved. It also means a backup holds exactly what the editor is showing you, unsaved edits included, which is usually what you want.

What it is allowed to touch

  • scripting: read the file list and contents from the editor tab you are on
  • downloads: save files into your Downloads folder
  • storage: remember your receiver address and password
  • script.google.com: the only site it runs on

No analytics and no servers. Nothing leaves your machine except the files you send to your own receiver.
